# pyqmd ↔ Node qmd command status

Quick reference for how close the Python rewrite is to the Node original,
command by command. Three questions per row:

1. **In pyqmd** — does the command exist at all?
2. **Matching parity** — does it return the same documents/results as Node
   for the same input? (Verified = covered by the
   [parity suite](parity/README.md); Unverified = probably fine, just never
   cross-checked against Node.)
3. **Output fidelity** — does the printed text (formatting, sections,
   coloring) match Node's, byte-for-byte-ish? Note: the automated parity
   suite deliberately _normalizes away_ exact text for most commands (see
   `parity/scenarios/cli_scenarios.py`'s docstrings) to avoid false
   negatives from cosmetic differences — so "✅" here usually means
   "manually diffed against real Node output and matched," not "covered by
   a regression test." Only `search`/`vsearch`/`query --format json` and
   the MCP tool surface get an automated byte-level check.

Legend: ✅ full/yes/verified · 🟡 partial/unverified/known differences ·
❌ not implemented · — not applicable

## Output formats (`--format`)

`cli` / `json` / `csv` / `md` / `xml` / `files` — all six values exist on
both sides for `search`/`vsearch`/`query` (and `multi-get` for `files`).
Only `json` is exercised by the parity suite; the other five are
implemented but unverified against Node's exact byte output.

## Performance (not a parity dimension, but worth knowing)

Not a command-status question, but surfaced by a new manual benchmark
(`just bench-scifact`, `parity/benchmark.py`): pyqmd's per-process MLX
model-load cost (~1.47s CPU-bound, safetensors deserialization + Metal
weight materialization) does **not** shrink on repeat launches the way
Node's mmap-backed GGUF loading does — there's no equivalent cheap-second-
run behavior to port. The practical fix isn't a faster load path, it's not
reloading at all: prefer `pyqmd mcp` (stdio or `--http`) over one CLI
process per query when issuing more than one embedding-backed query. A
real bug from this investigation is already fixed: `Store` was
eagerly importing the whole `mlx_embeddings → mlx_vlm → transformers`
chain (~700ms) at module level, taxing even pure-BM25 `search`/`status`/
`ls`/`get`; imports are now deferred into `embed.py`/`rerank.py`/
`expand.py`'s function bodies. `search` dropped from ~1.14s to ~0.45s
mean locally. See `parity/README.md`'s "Performance benchmark" section.

## Roadmap tie-back

- **#5 AST-aware chunking** — ✅ complete. `embed`/`query` both gained
  `--chunk-strategy <auto|regex>`; `status` gained an `AST Chunking`
  section. 6 languages (typescript, tsx, javascript, python, go, rust),
  ported from Node's `src/ast.ts` — one deliberate difference: JavaScript
  uses the dedicated `tree-sitter-javascript` grammar where Node reuses
  the TypeScript WASM for `.js` (equivalent captures for plain JS, and
  the ported JS query has no TS-only patterns). A 2026-09-20 post-merge
  review found 8 issues, all fixed: `embed --chunk-strategy auto` after a regex
  embed now re-chunks stale boundaries instead of no-op-ing (position-aware
  `index_content`/`count_pending_embed`, no schema change), a lone stray
  ` ``` ` marker no longer collapses a file to one chunk (unmatched marker
  ignored — deliberate divergence from Node, which extends it to EOF),
  invalid `chunk_strategy` raises `ValueError` at the Store boundary,
  `SKILL.md` lists `--chunk-strategy` for `query`, `status` parses a canned
  sample per language, AST break points are memoized (plus per-language
  `Parser` reuse), and the triple-duplicated break-point dedup lives in one
  helper. Plain `embed` (regex) never downgrades auto-produced boundaries.
- **#9 `cleanup`** — ✅ complete.
- **#10 CLI output formatting/parity polish** — ✅ complete. Closed out
  `status`'s missing sections, `ls`'s missing size/date/URI columns,
  `get`'s missing folder-context header, humanized timestamps, the byte-
  formatter spacing bug, and a real bold/dim/cyan/green/yellow color
  scheme across `status`/`get`/`context`/`collection`/`ls` (then
  excluding `update`/`embed`/`cleanup`; they gained Node's colors in the
  2026-09-24 output-text parity work below). `collection list`'s single-line
  format vs. Node's multi-line blocks slipped through #10 unaddressed at
  the time but has since been fixed too — see that row above.
- **#11 `skill`/`skills` commands** — ✅ complete (added 2026-09-17,
  shipped 2026-09-18). See the "Skill (agent-discoverability)" section
